# Лекция 13. Паттерн репозиторий и внедрение зависимостей

В предыдущей лекции запрос данных был написан прямо в компоненте. Такой подход работает, но плохо масштабируется: при росте приложения и появлении нескольких источников данных код становится запутанным. Лучшие практики рекомендуют разделять слой представления и слой данных.

В этом уроке вы отрефакторите приложение **Mars Photos**, выделив слой данных с помощью **паттерна репозиторий** и **внедрения зависимостей**.

### Необходимые условия

- Умение получать JSON из REST API и разбирать его в объекты.
- Умение использовать состояние и `useEffect`.
- Знание собственных хуков (лекция 10).

### Что вы узнаете

- Паттерн репозиторий.
- Внедрение зависимостей (dependency injection).
- Разделение обязанностей (separation of concerns).

### Что вы создадите

Вы разделите `Mars Photos` на слой представления и слой данных, реализуете репозиторий и внедрите его через React Context.

## Зачем нужны слои

Разделение на слои делает приложение:

- **масштабируемым** — легко добавить новый источник данных;
- **надёжным** — изменения в одном слое не ломают другой;
- **тестируемым** — репозиторий можно подменить в тестах.

**Рекомендуемая архитектура** предполагает как минимум два слоя:

- **Слой представления (UI)** — компоненты, отображающие данные.
- **Слой данных (Data)** — бизнес-логика, получение и сохранение данных.

Слой данных состоит из одного или нескольких **репозиториев**. Репозиторий, в свою очередь, обращается к **источникам данных** (сеть, база данных, файл).

## Источник данных

Вынесем сетевой запрос в отдельный источник данных:

```tsx
export type MarsPhoto = { id: number; title: string; url: string }

export interface MarsPhotosRemoteDataSource {
  getPhotos(): Promise<MarsPhoto[]>
}

export class NetworkMarsPhotosDataSource implements MarsPhotosRemoteDataSource {
  async getPhotos(): Promise<MarsPhoto[]> {
    const response = await fetch(
      'https://jsonplaceholder.typicode.com/photos'
    )
    if (!response.ok) throw new Error(`Ошибка сети: ${response.status}`)
    return (await response.json()) as MarsPhoto[]
  }
}
```

## Репозиторий

Репозиторий скрывает источник данных от остального приложения. Компоненты не знают, откуда приходят данные:

```tsx
export interface MarsPhotosRepository {
  getPhotos(): Promise<MarsPhoto[]>
}

export class DefaultMarsPhotosRepository implements MarsPhotosRepository {
  constructor(private remote: MarsPhotosRemoteDataSource) {}

  getPhotos(): Promise<MarsPhoto[]> {
    return this.remote.getPhotos()
  }
}
```

**Преимущество:** если позже данные будут кэшироваться в базе, изменится только репозиторий — компоненты останутся прежними. Это и есть **инкапсуляция**.

## Внедрение зависимостей через Context

**Внедрение зависимостей** — это передача зависимостей объекту извне, а не создание их внутри. В React удобный способ — контекст:

```tsx
import { createContext, useContext } from 'react'

const RepositoryContext = createContext<MarsPhotosRepository | null>(null)

export function RepositoryProvider({ children }: { children: React.ReactNode }) {
  const repository = new DefaultMarsPhotosRepository(new NetworkMarsPhotosDataSource())
  return (
    <RepositoryContext.Provider value={repository}>
      {children}
    </RepositoryContext.Provider>
  )
}

export function useRepository() {
  const repo = useContext(RepositoryContext)
  if (!repo) throw new Error('RepositoryProvider отсутствует')
  return repo
}
```

Такой контекст называют **контейнером внедрения зависимостей**: он создаёт зависимости в одном месте и раздаёт их всем, кому нужно.

## Слой представления

Хук получает репозиторий из контекста и управляет состоянием:

```tsx
type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }

function useMarsPhotos() {
  const repository = useRepository()
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    repository
      .getPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error) => setState({ status: 'error', message: error.message }))
  }, [repository])

  return state
}
```

Компонент вообще не занимается сетью:

```tsx
function MarsPhotosScreen() {
  const state = useMarsPhotos()

  if (state.status === 'loading') return <ActivityIndicator size="large" />
  if (state.status === 'error') return <Text>Ошибка: {state.message}</Text>
  return <Text>Получено фотографий: {state.photos.length}</Text>
}
```

## Полный код

```tsx
import { StatusBar } from 'expo-status-bar';
import { createContext, useContext, useEffect, useState } from 'react';
import { ActivityIndicator, StyleSheet, Text, View } from 'react-native';

type MarsPhoto = { id: number; title: string; url: string }

interface MarsPhotosRemoteDataSource {
  getPhotos(): Promise<MarsPhoto[]>
}

class NetworkMarsPhotosDataSource implements MarsPhotosRemoteDataSource {
  async getPhotos(): Promise<MarsPhoto[]> {
    const response = await fetch(
      'https://jsonplaceholder.typicode.com/photos'
    )
    if (!response.ok) throw new Error(`Ошибка сети: ${response.status}`)
    return (await response.json()) as MarsPhoto[]
  }
}

interface MarsPhotosRepository {
  getPhotos(): Promise<MarsPhoto[]>
}

class DefaultMarsPhotosRepository implements MarsPhotosRepository {
  constructor(private remote: MarsPhotosRemoteDataSource) {}
  getPhotos(): Promise<MarsPhoto[]> {
    return this.remote.getPhotos()
  }
}

const RepositoryContext = createContext<MarsPhotosRepository | null>(null)

function RepositoryProvider({ children }: { children: React.ReactNode }) {
  const repository = new DefaultMarsPhotosRepository(new NetworkMarsPhotosDataSource())
  return (
    <RepositoryContext.Provider value={repository}>
      {children}
    </RepositoryContext.Provider>
  )
}

function useRepository() {
  const repo = useContext(RepositoryContext)
  if (!repo) throw new Error('RepositoryProvider отсутствует')
  return repo
}

type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }

function useMarsPhotos(): UiState {
  const repository = useRepository()
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    repository
      .getPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error) => setState({ status: 'error', message: error.message }))
  }, [repository])

  return state
}

function MarsPhotosScreen() {
  const state = useMarsPhotos()
  if (state.status === 'loading') {
    return (
      <View style={styles.container}>
        <ActivityIndicator size="large" color="#3F51B5" />
      </View>
    )
  }
  if (state.status === 'error') {
    return (
      <View style={styles.container}>
        <Text style={styles.error}>Ошибка: {state.message}</Text>
      </View>
    )
  }
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Получено фотографий: {state.photos.length}</Text>
    </View>
  )
}

export default function App() {
  return (
    <RepositoryProvider>
      <MarsPhotosScreen />
      <StatusBar style="auto" />
    </RepositoryProvider>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24 },
  title: { fontSize: 22, fontWeight: 'bold', textAlign: 'center' },
  error: { fontSize: 18, color: 'red', textAlign: 'center' },
})
```

## Преимущества такого подхода

- Компоненты не знают о сети — их можно тестировать с фиктивным репозиторием.
- Источник данных легко заменить (сеть → база).
- Зависимости создаются в одном месте (контейнер внедрения зависимостей).

## Резюме

- Слой данных отделён от слоя представления.
- **Репозиторий** скрывает источники данных.
- **Внедрение зависимостей** через Context даёт слабую связанность.
- Компоненты получают данные через хук, не выполняя запросы сами.
